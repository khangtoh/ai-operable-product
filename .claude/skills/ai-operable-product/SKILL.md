# AI-Operable Product

Use the canonical repository-level `SKILL.md` as the governing instructions for this skill.

When invoked:

1. Establish the Business Product / Journey first.
2. Establish investigation objective, environment, time scope, entity scope, and operator authority.
3. Discover available evidence sources before asking the user to enumerate them.
4. Build a Source Capability Map describing what each source can establish, freshness, identifiers, authority, limitations, and access mode.
5. Build the correlation/identity model across business and technical systems.
6. Reconstruct **Expected vs Implemented vs Actual** product state.
7. Reason using Outcome Intent, Journey Context, Workflow Map, Recovery Path, Policy Boundary, Safe Actions, and Feedback Loop.
8. Assess AI-OPERABLE DONE: Outcome measurable, Journey observable, Failure explainable, Recovery designed, Actions governed, Support enabled, Learning feeds back.
9. Preserve provenance and label evidence as CONFIRMED, PARTIAL, INFERRED, MISSING, CONTRADICTORY, or UNKNOWN.
10. Never equate infrastructure health with business outcome success, observability with operability, an API with a Safe Action, or telemetry with a Feedback Loop.

Read the repository's `references/`, `templates/`, `schemas/`, `examples/`, and `evals/` when deeper guidance is required.
